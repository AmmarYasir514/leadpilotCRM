# LEADPILOT CRM 2.0 — SUPER ADMIN, USER MANAGEMENT & ACTIVITY MONITORING

## IMPORTANT ARCHITECTURAL UPDATE

Implement a comprehensive Super Admin management system as a core feature of LeadPilot CRM 2.0.

The Super Admin must have centralized control over all users, roles, permissions, CRM modules, lead assignments, sales activities, reports, and organization settings.

This functionality must be implemented starting in Phase 1, not postponed until the final phases.

All user activities must be linked to authenticated user accounts so the Super Admin can review individual and team performance.

---

# PHASE 1 — SUPER ADMIN & AUTHENTICATION

## 1. SUPER ADMIN ACCOUNT

Create a protected Super Admin role.

The initial Super Admin account must be created securely through an installation command or controlled setup process.

Never hardcode default production credentials.

The Super Admin can:

- Create new users
- Edit existing users
- Activate or deactivate users
- Suspend user accounts
- Reset user passwords securely
- Assign and remove roles
- Configure permissions
- Assign users to teams
- View all users
- View all leads and proposals
- View all sales pipelines
- View all follow-ups
- View all meetings
- View all user activities
- View individual performance
- View organization-wide reports
- Configure CRM settings
- Manage AI agent permissions
- Manage external integrations
- Export authorized business reports
- Review security and audit logs

The Super Admin role must be protected against accidental deletion or removal of the last active Super Admin.

For a future multi-tenant SaaS, distinguish between Platform Super Admin and Organization Admin. Platform Super Admin privileges must not automatically expose unrelated tenant business data.

Support these access scopes:

- Own records only
- Assigned records
- Team records
- Organization records

A Sales Representative can view and update only assigned leads.

A Sales Manager can view all leads and activities belonging to their team.

All permissions must be enforced in Laravel backend policies and database queries.

Hiding a frontend button is not sufficient security.

Permission changes must take effect promptly, including for already logged-in users.

## Activity Timeline

Create an employee activity timeline.

Example:

09:15 AM — User logged in

09:30 AM — Created new lead

10:10 AM — Generated AI proposal draft

10:25 AM — Marked proposal as submitted

11:40 AM — Completed client follow-up

02:00 PM — Attended scheduled meeting

03:20 PM — Updated opportunity status

Use actual event timestamps and the user's configured timezone.

## Activity Monitoring Rules

- Track meaningful CRM business events.
- Store actor, action, record type, record ID, timestamp, and relevant changes.
- Do not store passwords, access tokens, or confidential message contents in audit logs.
- Do not use hidden screenshots, keystroke logging, or invasive computer monitoring.
- Provide clear employee-facing information about activity logging.
- Allow authorized administrators to filter and export activity records.
- Keep audit logs protected from ordinary users.
- Define configurable retention periods.
- Preserve important audit events against unauthorized alteration.

Do not interpret login duration as actual productive working time.

# PHASE 10 — SECURITY & TESTING

Implement tests for:

1. Super Admin can create users.
2. Super Admin can edit users.
3. Super Admin can suspend users.
4. Suspended users cannot access protected routes.
5. Role permissions are enforced.
6. Users cannot escalate their own privileges.
7. Sales users cannot access restricted admin pages.
8. Sales users cannot access unauthorized leads.
9. Managers can access authorized team records.
10. Super Admin can review employee activity.
11. Activity logs record the correct actor.
12. Sensitive values are excluded from logs.
13. User reassignment preserves history.
14. AI agents respect user permissions.
15. Organization data remains isolated.
16. Last active Super Admin cannot be accidentally removed.
17. Permission changes invalidate stale access.
18. Exports respect authorization rules.

## FINAL REQUIREMENT

The Super Admin system must be fully functional and database-driven.

No hardcoded users, roles, permissions, performance statistics, or activity records.

The Super Admin must be able to manage the entire authorized CRM workspace through the interface without modifying source code.
